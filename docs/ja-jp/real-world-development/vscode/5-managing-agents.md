GitHub Copilot を agent mode で使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行などを自律的に行います。VS Code の Copilot Chat では、ツールの呼び出しやファイルの編集がリアルタイムで表示されます。エディターを離れずに差分を確認し、個々の変更を採用または取り消し、追加のプロンプトを送って作業を調整できます。

この演習では、次の内容を学習します。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューし、採用します。
- 進行中のセッションでエージェントに指示を送り、高コントラスト モードにライト モードも追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタム エージェントが、高コントラスト モードを実装しています。作業中にデザイン チームから、既定のテーマが暗すぎると感じる利用者向けのライト モードも追加してほしいという依頼がありました。新しい会話を最初から始めるのではなく、既存のセッションに指示を送り、作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが調べたファイル、実行したコマンド、提案した編集など、各手順が表示されます。ファイルの編集は差分と **Keep** / **Undo** の操作とともにチャットに表示されます。

1. 演習 4 の Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツールの呼び出しを確認します。ファイルの読み取りや編集、実行を求められたターミナル コマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がチャットに表示されます。
   - **Keep** を選択すると変更を採用します。
   - **Undo** を選択すると変更を取り消し、エージェントにもう一度作業させます。
4. チャット上部の **Files changed** を開くと、このセッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ツールの使用許可を求められることがあります（たとえば、ターミナル コマンドの実行）。その場合、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可してもよいコマンドだけを承認してください。

5. エージェントが高コントラスト モードを実装し終えるまで待ちます。最後に、行った変更の概要が表示されます。

## エージェントにライト モードの追加を依頼する

高コントラスト モードができたら、同じ会話でライト モードの切り替え機能も追加します。会話を続けるため、エージェントは変更したコンポーネント、スタイルの方針、設定をローカル ストレージに保存する方法など、先ほどの作業のコンテキストを引き継ぎます。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントが既存の変更を確認し、ライト モードの追加を提案する様子を見ます。
3. 高コントラスト モードの場合と同様に、新しい編集を確認します。各差分で **Keep** または **Undo** を選択します。
4. エージェントが意図しない方向に進んだ場合（たとえば、気に入らない方法でトグルのユーザー インターフェイス (UI) をリファクタリングする場合）は、チャット入力欄の横にある **Stop** を選択して停止し、明確な追加プロンプトを送信します。

> [!TIP]
> 進行中のセッションに指示を送ると、最初からやり直すより効率的です。追加のプロンプトで変更を依頼できます（「Cascading Style Sheets (CSS) を簡潔にして、セレクターの重複ではなく CSS 変数を使ってください」）。軌道修正もできます（「トグルを 3 つに増やさず、ライト モードを既存の設定パネルに追加してください」）。作業範囲の拡張もできます（「両方の切り替えにキーボード ショートカットも追加してください」）。

## 作業内容をレビューする

コミットする前に、エージェントが変更した内容をすべて確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧全体を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタム エージェントのアクセシビリティ パターン（Accessible Rich Internet Applications (ARIA) 属性、キーボード操作、セマンティックな HyperText Markup Language (HTML)、ローカル ストレージへの保存）が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで変更を公開します。

## まとめと次のステップ

Copilot Chat の agent mode で、進行中のセッションを監視して調整しました。ファイル編集を一つずつ確認し、変更を採用または取り消し、コンテキストを保ったまま追加プロンプトを送って作業を拡張しました。

このレッスンでは、次の内容を確認しました。

- エージェントの作業をリアルタイムで監視する方法
- 個々のファイル編集を採用または取り消す方法
- 追加プロンプトで進行中のセッションを調整する方法

[次のレッスン][next-lesson]では、アクセシビリティ対応の変更をプル リクエストとして公開し、このラボでローカルのカスタム エージェントが作成した変更をレビューします。
